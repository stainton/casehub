后端 API

服务器提供状态、业务操作与 agent 设置接口。相对地址与网站同源，目前未启用身份认证。

GET /api/state

读取完整状态，无请求参数。首次访问时初始化示例主线。

查看当前 JSON 状态 ↗
{
  "mainRevision": 1,
  "versions": [],
  "folders": [],
  "cases": [],
  "histories": [],
  "records": [],
  "tasks": [],
  "reqFolders": [],
  "reqDocs": [],
  "pendingFolders": [],
  "pendingCases": [],
  "scripts": []
}

上例仅展示响应结构。versions 使用 id、name、mainline、baseMainRevision、createdBy、createdAt 等小写开头字段；其他实体使用 ID、VersionID、CreatedAt 等大写开头字段。

histories 包含 Before / After 用例快照和 SourceVersionID；records 包含 Result、Note（Markdown 文本）、Submitted 和 TaskID。日期为 RFC 3339 字符串。

scripts 是"自动化管理"页的自动化脚本，每条脚本对应一条用例（VersionID + CaseID 唯一），字段有 FileName、Language、Code、Status（generated / blocked）、Summary、Deviations（{Risk, Summary}）、JobID，以及 FromPreconditions / FromSteps / FromExpected —— 生成时的用例原文快照，与用例当前内容比较即可判断脚本是否已过时。脚本不单独保存目录：脚本树直接用所属用例当前所在的目录，因此与用例树同名同构。脚本随用例或版本一起删除，创建版本和同步/合并不复制脚本。

pendingCases 是需求管理"用例评审"页的临时草稿区，字段与 cases 类似，另有 Review（空 / passed / rejected）、ReviewedBy、ReviewedAt；不属于任何版本。导入（见 importPendingCases）默认整体清空该区，也可通过 CaseIDs 只导入并移除部分用例。

POST /api/action

请求头：Content-Type: application/json。请求体上限为 1 MiB。Type 指定操作，Author 可选，默认“本地用户”。除创建版本外，以下操作均针对非主线 VersionID。

展开下方操作可查看请求示例。示例中的版本、文件夹和用例 ID 需替换为当前状态中的实际值。

createVersion · 创建测试版本

完整复制主线目录和用例，版本名称不能为空或重复。

{
  "Type": "createVersion",
  "Author": "本地用户",
  "Name": "v2.0 回归"
}
createFolder · 新建文件夹

ParentID 可省略以创建根目录；指定父目录时必须存在。

{
  "Type": "createFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "ParentID": "root",
  "Name": "支付"
}
renameFolder · 重命名文件夹

允许重命名主线或测试版本中的任意文件夹，不影响其中的子目录和用例。

{
  "Type": "renameFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "文件夹ID",
  "Name": "支付流程"
}
createCase · 新增用例

标题和有效目录必填。CaseID 可选，默认自动生成，当前版本内不能重复。

{
  "Type": "createCase",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "auth",
  "Title": "登录成功",
  "Priority": "P0",
  "Preconditions": "账号已启用",
  "Steps": "输入正确密码",
  "Expected": "进入首页",
  "Description": "评审时人工填写的用例描述（可选）"
}
editCase · 编辑用例

文本字段为整体替换，未提供的字段会置空；保存编辑前后快照。

{
  "Type": "editCase",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Title": "登录成功",
  "Priority": "P0",
  "Preconditions": "账号已启用",
  "Steps": "输入正确密码",
  "Expected": "进入首页",
  "Description": "评审时人工填写的用例描述（可选）"
}
saveRecord · 保存测试记录草稿

每次调用新增一条草稿，同时更新用例结果。没有修改已有记录的接口。

{
  "Type": "saveRecord",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Result": "passed",
  "Note": "## 执行环境\nChrome\n\n**结果**：通过"
}
submitRecord · 提交测试记录

新增不可修改的已提交记录，同时更新用例结果；TaskID 可选。Result 为 passed / failed / blocked。

{
  "Type": "submitRecord",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Result": "failed",
  "Note": "**实际结果**：错误提示"
}
createTask · 创建测试任务

任务名称和用例列表不能为空；用例必须属于该版本且不能重复。

{
  "Type": "createTask",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "Name": "冒烟测试",
  "CaseIDs": [
    "CASE-0001"
  ]
}
sync · 拉取主线更新

合入主线新增目录、用例和无冲突文本；冲突文本保留在分支，warnings 返回冲突提示。

{
  "Type": "sync",
  "Author": "本地用户",
  "VersionID": "版本ID"
}
merge · 合并到主线

将版本新增目录、变更用例合入主线。文本冲突返回 409，需要先同步并人工处理。

{
  "Type": "merge",
  "Author": "本地用户",
  "VersionID": "版本ID"
}
mergeFolder · 合并文件夹到主线

将分支中一个文件夹的子树（含其中变更用例）整体合入主线，挂到 TargetFolderID 指定的主线目标文件夹下，保留子树内部结构。仅能合并尚未在主线出现过的文件夹（即分支本地新建的目录）；若目标文件夹下已有同名子文件夹，整体失败并返回错误，不写入任何内容。子树内的文本冲突返回 409，需要先同步并人工处理。

{
  "Type": "mergeFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "分支中的文件夹ID",
  "TargetFolderID": "主线目标文件夹ID"
}
mergeCases · 合并用例到主线

将 CaseIDs 指定的一批用例（可来自不同文件夹、可来自勾选或搜索结果）平铺合入 TargetFolderID 指定的主线父文件夹，不保留源目录结构。需要保留完整目录树时，请使用文件夹右键菜单中的 mergeFolder。主线不存在的用例会直接合入，不受分支 Dirty 标记影响；主线已有但未变更的用例会被跳过，若全部跳过则在响应 warnings 中提示“没有可合并的变更”。文本冲突返回 409。

{
  "Type": "mergeCases",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseIDs": [
    "CASE-0001",
    "CASE-0002"
  ],
  "TargetFolderID": "主线父文件夹ID"
}
moveFolder · 移动文件夹

仅测试版本。连同子文件夹和用例一起移动到 TargetFolderID 下；根目录不能移动，不能移动到自身或其子文件夹下。移动在「合并到主线」（merge）时同步到主线；「拉取主线」（sync）时，本版本未移动过的文件夹会跟随主线的移动。

{
  "Type": "moveFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "auth",
  "TargetFolderID": "目标文件夹ID"
}
deleteFolder · 删除空文件夹

允许删除主线或分支内没有子目录和用例的空文件夹；不能删除根目录 root。

{
  "Type": "deleteFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "待删除的空文件夹ID"
}
moveCases · 批量移动用例

将 CaseIDs 指定的一批用例移动到同一分支内 TargetFolderID 指定的另一个文件夹；已在目标文件夹的用例会被跳过。移动会把用例标记为 Dirty 并记录一条 Action 为 move 的编辑历史，之后随任意一种合并方式带到主线。

{
  "Type": "moveCases",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseIDs": [
    "CASE-0001"
  ],
  "TargetFolderID": "同一分支内的目标文件夹ID"
}
createPendingFolder · 新建待评审文件夹

ParentID 可省略以创建根目录下的文件夹；指定父目录时必须存在。与主线/测试版本的目录树完全独立。Code 可选，表示该文件夹对应的用例编号前缀：需求缩写、需求缩写-模块缩写 或 需求缩写-模块缩写-测试类别；Name 仍用中文描述。AI 设计导入时自动设置。

{
  "Type": "createPendingFolder",
  "Author": "本地用户",
  "ParentID": "pending-root",
  "Name": "功能测试",
  "Code": "LOGIN-AUTH-FUNC"
}
renamePendingFolder · 重命名空待评审文件夹

仅允许重命名没有子目录和用例的文件夹。

{
  "Type": "renamePendingFolder",
  "Author": "本地用户",
  "FolderID": "文件夹ID",
  "Name": "支付流程"
}
createPendingCase · 新增待评审用例

标题和有效目录必填，用例 ID 自动生成。新建的用例评审状态为空（未评审）。所在文件夹的 Code 形如 LOGIN-AUTH-FUNC（需求缩写-模块缩写-测试类别，类别为 FUNC/REL/PERF/SEC/COMPAT/UX）时，编号自动取 TC-LOGIN-AUTH-FUNC-NNN，NNN 接着待评审区和各版本中该前缀的最大编号递增；其他文件夹下为随机编号。

{
  "Type": "createPendingCase",
  "Author": "本地用户",
  "FolderID": "pending-root",
  "Title": "退款成功",
  "Priority": "P1",
  "Preconditions": "订单已支付",
  "Steps": "发起退款",
  "Expected": "退款到账",
  "Description": "评审时人工填写的用例描述（可选）"
}
editPendingCase · 编辑待评审用例

文本字段整体替换；保存后评审状态会被重置为未评审，需要重新评审。

{
  "Type": "editPendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF",
  "Title": "退款成功",
  "Priority": "P1",
  "Preconditions": "订单已支付",
  "Steps": "发起退款",
  "Expected": "退款到账",
  "Description": "评审时人工填写的用例描述（可选）"
}
movePendingFolder · 移动待评审文件夹

连同子文件夹和用例一起移动到 TargetFolderID 下；pending-root 不能移动，不能移动到自身或其子文件夹下。

{
  "Type": "movePendingFolder",
  "Author": "本地用户",
  "FolderID": "待评审文件夹ID",
  "TargetFolderID": "pending-root"
}
setReqDocCode · 设置需求缩写

Code 为 2–12 位大写英文字母或数字、以字母开头、不含 -，不能与其他需求重复；传空字符串清除。它是 AI 设计用例编号 TC-<需求缩写>-<模块>-<类别>-NNN 的第二段，AI 设计抽屉确认时自动保存。

{
  "Type": "setReqDocCode",
  "Author": "本地用户",
  "DocID": "REQ-0001",
  "Code": "LOGIN"
}
describePendingCase · 填写待评审用例描述

只替换 Description（去除首尾空白，可置空），不影响其他字段，也不会重置评审状态。Description 是评审发起人阅读用例后写的总结，AI 设计不会填写。

{
  "Type": "describePendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF",
  "Description": "覆盖退款到账的主流程"
}
deletePendingCase · 删除待评审用例

直接从待评审区移除，不可恢复。

{
  "Type": "deletePendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF"
}
deletePendingCases · 批量删除待评审用例

CaseIDs 必填且非空，直接从待评审区移除，不可恢复。全部成功或全部失败：任一 ID 不存在时不删除任何用例，并返回 400 列出不存在的 ID。

{
  "Type": "deletePendingCases",
  "Author": "本地用户",
  "CaseIDs": ["TC-LOGIN-AUTH-FUNC-001", "TC-LOGIN-AUTH-FUNC-002"]
}
reviewPendingCase · 评审用例

Review 为 passed 或 rejected。

{
  "Type": "reviewPendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF",
  "Review": "passed"
}
importPendingCases · 导入已评审用例

VersionID 必须是非主线的测试版本。CaseIDs 可选：省略或为空时导入整个待评审区，成功后该区会被清空并重置为空的 pending-root；指定时只导入这些用例（用于按目录或单条用例导入），成功后只移除这些用例，其余待评审用例和目录结构保持不变。要求范围内用例非空且全部评审通过，否则返回 400 并列出未通过的用例。TargetFolderID 可选，为目标版本中的父目录，默认 root（全部用例）。SourceFolderID 可选，为待评审区中映射到该父目录的来源文件夹（默认 pending-root，导入整个待评审区时不可指定），范围内用例必须都在它之下，它下面的子目录原样重建：例如待评审区 A/B/C/D 中勾选 B 导入时传 SourceFolderID=A，结果为 <父目录>/B/C/D。按目录结构合并进目标版本：同名目录复用，用例按标题在对应目录下查重，范围内任意冲突则本次导入整体失败、不写入任何内容。

{
  "Type": "importPendingCases",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseIDs": ["待评审用例ID"]
}
saveScript · 保存自动化脚本

按 (VersionID, CaseID) 更新或新建脚本，一条用例只有一个脚本，重新生成会原地覆盖。主线也允许保存：脚本是可重新生成的产物，不算用例内容，不会改变用例的 Dirty / Revision。服务端把当前用例的前置条件/步骤/预期结果记为 From* 快照（不采用调用方提供的值），用例之后被编辑即判定脚本过时。ScriptStatus 为 blocked 时 ScriptCode 可以为空，用 ScriptSummary 说明缺少什么。

{
  "Type": "saveScript",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "ScriptFileName": "CASE-0001.spec.ts",
  "ScriptLanguage": "typescript",
  "ScriptStatus": "generated",
  "ScriptCode": "import { test, expect } from '@playwright/test';\n…",
  "ScriptSummary": "验证错误密码被拒绝",
  "ScriptJobID": "生成任务ID（可选）",
  "ScriptDeviations": [
    { "Risk": "medium", "Summary": "错误提示文案与用例不同" }
  ]
}
deleteScripts · 删除自动化脚本

删除同一版本下多条用例的脚本，用例本身不受影响，可以重新生成。主线同样允许。列表中有任何一条没有脚本则整体失败。

{
  "Type": "deleteScripts",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseIDs": [
    "CASE-0001"
  ]
}

Agent 设置

GET /api/agent-settings/{agent} 读取业务默认参数；PUT 保存完整的 {baseUrl, instructions, testAccount, testSecret, timeoutMinutes} 对象。{agent} 为 playwright（用例设计）或 generator（脚本生成），未知 agent 返回 404。超时时间为 1–240 分钟。配置存在 CaseHub 的 agent 配置表里（PostgreSQL 为 casehub_agent_settings），与状态文档分开保存；保存业务默认参数不会改变配置版本号。

GET /api/agent-settings/{agent}/runtime 返回 {content, revision, exists, updatedAt}：content 是该 agent 的 setting.json 完整正文，按原文保存，未知字段照样保留；exists 为 false 表示 CaseHub 还没保存过配置（revision 为 "0"），agent 使用镜像内自带的配置。PUT 提交 {content, revision}，revision 与存储中的不一致返回 409（有人在此期间保存过），JSON 或 env/model 类型无效返回 400；正文有变化时版本号 +1。CaseHub 不访问 agent 的文件系统：发起任务时把这份配置和版本号放进请求体的 agentSettings（{revision, content}）下发，agent 据此覆写自己的 setting.json，下次调用 Claude CLI 生效，无需重启。

资产 /api/assets

GET /api/assets[?type=image|video|audio] 返回元数据数组（新的在前）；POST 为 multipart/form-data，字段 type、file、可选 name，上限图片 15 MB / 音频 50 MB / 视频 200 MB。GET /api/assets/{id} 返回原始文件，DELETE 删除，不存在返回 404。

GET /api/assets/{id} 只用于界面预览，agent 不会访问它。向 /api/planner/jobs 提交任务时可在 context.assetIds 里带资产 id：代理先把文件推给 agent（HEAD/PUT /v1/planner/assets/{sha256}，agent 已缓存的不重复发送），再把 assetIds 替换成 context.assets（{id, name, type, mimeType, sha256, size}）转发。已删除的 id 被忽略；assetIds 不是字符串数组返回 400 PLANNER_INVALID_REQUEST，CaseHub 读取失败返回 500、agent 收不下资产返回 502，均为 PLANNER_ASSETS_UNAVAILABLE。

AI 设计代理 /api/planner/*

需求管理页"AI 设计"抽屉使用的透明反向代理，转发到 auto-test 仓库的 planner HTTP 服务（server/planner/），路径 /api/planner/xxx 会被重写为该服务的 /v1/planner/xxx，直接转发，无需鉴权 Token；POST 请求体会带上该 agent 存储的 Claude 配置 agentSettings，读不到配置时返回 500 PLANNER_SETTINGS_UNAVAILABLE。完整的任务提交/进度/结果契约见该服务自己的 OpenAPI 文档，这里不重复。

提交设计任务时，前端会带上抽屉里填写的 timeoutMs（任务超时时间，1 分钟–4 小时），覆盖 planner 服务的默认时限；服务端仍按自己的上限封顶，实际生效值回写在任务状态的 timeoutMs 上。

GET /api/planner/status 是 CaseHub 本地接口（不经过代理），返回 {"enabled": bool} 表示 planner 代理是否启用。默认连接 http://localhost:4501，可通过 CASEHUB_PLANNER_URL 修改。

脚本生成代理 /api/generator/*

用例管理"脚本生成"抽屉使用的透明反向代理，转发到 auto-test 仓库的 generator HTTP 服务（server/generator/），路径 /api/generator/xxx 会被重写为该服务的 /v1/generator/xxx，直接转发，无需鉴权 Token；POST 请求体同样带上该 agent 存储的 Claude 配置 agentSettings，读不到配置时返回 500 GENERATOR_SETTINGS_UNAVAILABLE。任务提交/进度/结果契约见该服务自己的 OpenAPI 文档。CaseHub 提交的是已评审导入版本的用例原文（可附带需求文档作背景），任务成功后前端逐条调用 saveScript 落库，因此脚本本身保存在 CaseHub 状态里，而不是留在生成服务中。

GET /api/generator/status 是 CaseHub 本地接口（不经过代理），返回 {"enabled": bool}。默认连接 http://localhost:4502，可通过 CASEHUB_GENERATOR_URL 修改。两个服务相互独立，可以只启用其中一个。

响应与错误

成功返回 HTTP 200：

{ "state": { "mainRevision": 1, "versions": [], "folders": [], "cases": [], "histories": [], "records": [], "tasks": [] }, "warnings": ["可选的提示信息"] }

warnings 和 conflicts 为空时省略。客户端保存成功后应采用返回的完整 state 刷新页面。

状态码含义
400无效 JSON、未知操作或业务校验失败；操作接口存储错误也返回 400。
409主线文本已更新，需处理冲突。
500读取状态时存储异常。
{ "error": "主线已有更新，需要先同步并处理冲突", "conflicts": ["CASE-0001"] }

错误响应包含 error；操作错误还包含 conflicts（可能为 null）。编辑用例、保存或提交记录时，人工确认后可使用 Force: true；合并操作不会通过 Force 跳过冲突。保存记录时 Submitted: true 也会生成已提交记录。
