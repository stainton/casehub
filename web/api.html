后端 API

当前服务器提供两个 JSON 接口。相对地址与网站同源，目前未启用身份认证。

GET /api/state

读取完整状态，无请求参数。首次访问时初始化示例主线。

查看当前 JSON 状态 ↗
{
  "mainRevision": 1,
  "versions": [],
  "folders": [],
  "cases": [],
  "histories": [],
  "records": [],
  "tasks": [],
  "reqFolders": [],
  "reqDocs": [],
  "pendingFolders": [],
  "pendingCases": []
}

上例仅展示响应结构。versions 使用 id、name、mainline、baseMainRevision、createdBy、createdAt 等小写开头字段；其他实体使用 ID、VersionID、CreatedAt 等大写开头字段。

histories 包含 Before / After 用例快照和 SourceVersionID；records 包含 Result、Note（Markdown 文本）、Submitted 和 TaskID。日期为 RFC 3339 字符串。

pendingCases 是需求管理"用例评审"页的临时草稿区，字段与 cases 类似，另有 Review（空 / passed / rejected）、ReviewedBy、ReviewedAt；不属于任何版本，导入成功后会被清空。

POST /api/action

请求头：Content-Type: application/json。请求体上限为 1 MiB。Type 指定操作，Author 可选，默认“本地用户”。除创建版本外，以下操作均针对非主线 VersionID。

展开下方操作可查看请求示例。示例中的版本、文件夹和用例 ID 需替换为当前状态中的实际值。

createVersion · 创建测试版本

完整复制主线目录和用例，版本名称不能为空或重复。

{
  "Type": "createVersion",
  "Author": "本地用户",
  "Name": "v2.0 回归"
}
createFolder · 新建文件夹

ParentID 可省略以创建根目录；指定父目录时必须存在。

{
  "Type": "createFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "ParentID": "root",
  "Name": "支付"
}
renameFolder · 重命名空文件夹

仅允许重命名没有子目录和用例的文件夹。

{
  "Type": "renameFolder",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "文件夹ID",
  "Name": "支付流程"
}
createCase · 新增用例

标题和有效目录必填。CaseID 可选，默认自动生成，当前版本内不能重复。

{
  "Type": "createCase",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "FolderID": "auth",
  "Title": "登录成功",
  "Priority": "P0",
  "Preconditions": "账号已启用",
  "Steps": "输入正确密码",
  "Expected": "进入首页"
}
editCase · 编辑用例

文本字段为整体替换，未提供的字段会置空；保存编辑前后快照。

{
  "Type": "editCase",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Title": "登录成功",
  "Priority": "P0",
  "Preconditions": "账号已启用",
  "Steps": "输入正确密码",
  "Expected": "进入首页"
}
saveRecord · 保存测试记录草稿

每次调用新增一条草稿，同时更新用例结果。没有修改已有记录的接口。

{
  "Type": "saveRecord",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Result": "passed",
  "Note": "## 执行环境\nChrome\n\n**结果**：通过"
}
submitRecord · 提交测试记录

新增不可修改的已提交记录，同时更新用例结果；TaskID 可选。Result 为 passed / failed / blocked。

{
  "Type": "submitRecord",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "CaseID": "CASE-0001",
  "Result": "failed",
  "Note": "**实际结果**：错误提示"
}
createTask · 创建测试任务

任务名称和用例列表不能为空；用例必须属于该版本且不能重复。

{
  "Type": "createTask",
  "Author": "本地用户",
  "VersionID": "版本ID",
  "Name": "冒烟测试",
  "CaseIDs": [
    "CASE-0001"
  ]
}
sync · 拉取主线更新

合入主线新增目录、用例和无冲突文本；冲突文本保留在分支，warnings 返回冲突提示。

{
  "Type": "sync",
  "Author": "本地用户",
  "VersionID": "版本ID"
}
merge · 合并到主线

将版本新增目录、变更用例合入主线。文本冲突返回 409，需要先同步并人工处理。

{
  "Type": "merge",
  "Author": "本地用户",
  "VersionID": "版本ID"
}
createPendingFolder · 新建待评审文件夹

ParentID 可省略以创建根目录下的文件夹；指定父目录时必须存在。与主线/测试版本的目录树完全独立。

{
  "Type": "createPendingFolder",
  "Author": "本地用户",
  "ParentID": "pending-root",
  "Name": "支付"
}
renamePendingFolder · 重命名空待评审文件夹

仅允许重命名没有子目录和用例的文件夹。

{
  "Type": "renamePendingFolder",
  "Author": "本地用户",
  "FolderID": "文件夹ID",
  "Name": "支付流程"
}
createPendingCase · 新增待评审用例

标题和有效目录必填，用例 ID 自动生成。新建的用例评审状态为空（未评审）。

{
  "Type": "createPendingCase",
  "Author": "本地用户",
  "FolderID": "pending-root",
  "Title": "退款成功",
  "Priority": "P1",
  "Preconditions": "订单已支付",
  "Steps": "发起退款",
  "Expected": "退款到账"
}
editPendingCase · 编辑待评审用例

文本字段整体替换；保存后评审状态会被重置为未评审，需要重新评审。

{
  "Type": "editPendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF",
  "Title": "退款成功",
  "Priority": "P1",
  "Preconditions": "订单已支付",
  "Steps": "发起退款",
  "Expected": "退款到账"
}
deletePendingCase · 删除待评审用例

直接从待评审区移除，不可恢复。

{
  "Type": "deletePendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF"
}
reviewPendingCase · 评审用例

Review 为 passed 或 rejected。

{
  "Type": "reviewPendingCase",
  "Author": "本地用户",
  "CaseID": "CASE-ABCDEF",
  "Review": "passed"
}
importPendingCases · 导入已评审用例

VersionID 必须是非主线的测试版本。要求待评审区非空且全部用例评审通过，否则返回 400 并列出未通过的用例。按目录结构合并进目标版本：同名目录复用，用例按标题在对应目录下查重，任意冲突则整体导入失败、不写入任何内容。成功后待评审区会被清空。

{
  "Type": "importPendingCases",
  "Author": "本地用户",
  "VersionID": "版本ID"
}

AI 设计代理 /api/planner/*

需求管理页"AI 设计"抽屉使用的透明反向代理，转发到 auto-test 仓库的 planner HTTP 服务（server/planner/），路径 /api/planner/xxx 会被重写为该服务的 /v1/planner/xxx，直接转发，无需鉴权 Token。完整的任务提交/进度/结果契约见该服务自己的 OpenAPI 文档，这里不重复。

GET /api/planner/status 是 CaseHub 本地接口（不经过代理），返回 {"enabled": bool} 表示 planner 代理是否启用。默认连接 http://localhost:4501，可通过 CASEHUB_PLANNER_URL 修改。

响应与错误

成功返回 HTTP 200：

{ "state": { "mainRevision": 1, "versions": [], "folders": [], "cases": [], "histories": [], "records": [], "tasks": [] }, "warnings": ["可选的提示信息"] }

warnings 和 conflicts 为空时省略。客户端保存成功后应采用返回的完整 state 刷新页面。

状态码含义
400无效 JSON、未知操作或业务校验失败；操作接口存储错误也返回 400。
409主线文本已更新，需处理冲突。
500读取状态时存储异常。
{ "error": "主线已有更新，需要先同步并处理冲突", "conflicts": ["CASE-0001"] }

错误响应包含 error；操作错误还包含 conflicts（可能为 null）。编辑用例、保存或提交记录时，人工确认后可使用 Force: true；合并操作不会通过 Force 跳过冲突。保存记录时 Submitted: true 也会生成已提交记录。
